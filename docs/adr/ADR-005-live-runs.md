# ADR-005: Live runs with a steppable engine and typed channels

- Status: Accepted
- Date: 2026-11-22

## Context

Phase 4 streams metrics while a simulation runs, with start, pause, resume, stop and a speed
control. Live and instant runs must never disagree.

## Decision

1. **One engine, two drivers.** `sim::engine::Simulation` advances with `step_until(t)`. The
   instant run is one call to it; a live run calls it once per simulated second. Ticks only read
   state (utilization uses a separate unclipped accumulator), so any stepping pattern gives a
   byte-identical report. A test enforces this.
2. **Controller on its own thread** (`sim::live`), with no Tauri types: events go to a `sink`
   closure, which makes it unit-testable with plain channels. One live run at a time; starting a
   second returns an error. Pause, stop and speed use atomics and are polled every 25 ms.
3. **Pacing**: simulated seconds per real second (0.1 to 1000), or unlimited. After a pause the
   clock restarts, so the run never bursts to "catch up".
4. **Transport**: a typed `tauri::ipc::Channel<LiveEvent>` (tick, finished, stopped, failed)
   generated by tauri-specta (ADR-003). Per-run and ordered, unlike global events.
5. **UI**: events are buffered and drawn every 250 ms, so max speed cannot flood React. Charts are
   plain SVG, no chart library. Leaving the Simulate tab stops the run.
6. **Out of scope**: changing traffic or topology mid-run (Phase 7), keeping run history
   (Phases 8 and 9), a real HTTP load generator (Phase 6).

## Consequences

- No new dependencies.
- The engine's per-second timeline and the live ticks are the same numbers.
